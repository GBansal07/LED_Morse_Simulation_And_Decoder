# LED_Morse_Simulation_And_Decoder
I created an LED Morse Decoder for my UWindsor Mars Rover Team that competes in the Canadian International Rover Challenge. I also created my own simulation with a few randomized parameters using an LED. The Morse Decoder program is in the same file and works normally because I use millis() for non-blocking functionality.

Now here are my thoughts and design process for this project:
The first thing I did was learn a sufficient amount of Morse code to be able to program logic into an Arduino, converting LED timing intervals into numbers and letters. After some research about Morse, I constructed a simulation to randomly generate an alphanumeric code (fancy word for a code that only consists of the English letters and numbers), convert it to Morse (dots and dashes), then to timings, and blink an LED I wired to an Arduino NANO through a breadboard. I laid this out in a clear and concise way, but actually doing it took lots of time. Coming into this project, I knew a bit about wiring electrical components, and I was very familiar with using Arduinos for hobby projects, but I was not comfortable with programming in the Arduino IDE/C++ enough for such a programming-dependent project. So, the first thing I did was get to learning through the latest free version of Claude. I learned a lot about arrays, like using a char array for letters/numbers and char* for the Morse code that corresponds to each, and they have the same index in each array, so it was easy to communicate with other functions in the code. I completely randomized as many parameters as I could as well, just so my decoder could be prepared for different codes at competition. The code was randomly picked 8-12 characters and sometimes included 1 or 2 spaces, and as for the Morse unit of time, the CIRC website released that it was 66 ms, but before I would generate a random number between 200-600ms. From this, I generated the code, and all I had to do was convert random letters/numbers to Morse code, then use the Morse unit to calculate on and off timings that would be stored in two other arrays. To finish off the simulation part of the project, I took the on/off timings that were stored and used the millis() function on the LED to tell it how long it needed to be on or off by just flipping back and forth between the on and off timing arrays. I learned quite a bit about millis(), like that it’s more preferred to use instead of delay() because delay() stops the entire program, while millis() keeps it running, hence why millis() is referred to as non-blocking. The main reason why I used millis() is that I was planning on using the same microcontroller to read the LED Morse code, so I couldn’t stop the code whenever I wanted to blink the LED, because I needed to time the on and off times that my decoder would read from the LED to get information and translate the code.
	
Next, I developed a decoder using a light-dependent resistor (LDR) to detect the light from the LED. I would get the delta of the times from calling the millis() function at the start and end, both when the LED is on and off, then store the timings in an array. Then, from the array, I would use the given 66ms Morse unit with some tolerance to convert the on and off timings into Morse, then from the Morse, I would go back and forth between the Morse arrays to construct the alphanumeric code.

Prototyping obviously didn’t go smoothly; I made so many mistakes. One of my most memorable mistakes was that I, without much thought, wired an LDR with an analog pin on one end and the other end going through ground. I quickly found that I was reading nothing when I would test my values on the Serial Monitor. This mistake taught me a lot about LDRs and why they are wired the way they are for an application where they are used as a sensor. An LDR is simply a resistor, so wiring it in a loop with the Arduino gives no information, since the analog pin that it’s connected to reads changes in voltage. With the resistor in a closed loop, there’s no variable voltage, so I got no meaningful information from the sensor. With this issue, I searched for how to wire an LDR with an Arduino and found that I had to create a voltage divider. The way it works is: I put the analog pin node, connected to the Arduino, between the static resistor and the light-dependent one and measure the change in voltage between them. This gave me a number between 0 and 1023 that I could use as a “light level” to help me identify when the LED is on or off. As for programming, I would write code and explain my logic function-by-function to Claude and have it teach me where my programming logic is flawed. With the AI, I would work with it by writing my logic in the prompt rather than just letting it do its own thing, and I can’t understand and bugfix. This process takes longer, but I got to learn lots about concepts like the different ways to use the millis() function and how to work with random-size arrays with null terminators.

 After prototyping, I designed a PCB in KiCad from scratch by learning the steps and UI from YouTube tutorials, then drawing out the circuit I designed with the prototype. After designing, I sent my Gerber files to the IDEA Lab at UWindsor to get my PCBs printed, and then I soldered my electronics onto them.
